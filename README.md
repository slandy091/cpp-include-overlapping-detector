# C++ include overlapping detector: плагин для VS Code

**Автор:** Гарифулин Павел ИСУ - 558931, группа M3101\
**IDE:** Visual Studio Code\
**Язык реализации:** TypeScript

Расширение для Visual Studio Code, которое находит циклические зависимости между заголовочными файлами C++ (`#include`-циклы) и показывает, по какой цепочке файлов цикл образуется.

## Архитектура
 
### Состав плагина
 
#### Модули

- [extension](docs/extension/README.md)
- [graph](docs/graph/README.md)
- [parser](docs/parser/README.md)


| Компонент | Файл | Роль |
|---|---|---|
| Манифест | `package.json` | Объявляет команду и точку входа (`main`) |
| Точка входа | `src/extension.ts`, функция `activate` | Регистрирует команду, проверяет редактор и открытую папку, запускает обход файлов, показывает результат |
| Разбор `#include` | `src/parser.ts`, функции `parseIncludes` и `cleanFile` | Принимает текст файла, возвращает список путей из `#include "..."` без учёта комментариев |
| Граф зависимостей | `src/graph.ts`, класс `DependencyGraph` | Хранит рёбра «файл -> подключаемый файл» и ищет цикл |
 
Манифест и код связаны идентификатором команды `cpp-include-overlapping-detector.analyze`: он указан в `package.json` и в вызове `registerCommand`.
  
### Функция `cleanFile`

Проходит по тексту слева направо и находится в одном из четырёх состояний. Главная идея: `//` и `/*` считаются началом комментария только в состоянии «Код», поэтому директивы внутри строк и комментариев не попадают в результат ошибочно.

| Состояние | Что происходит | Переход |
|---|---|---|
| Код | Символ копируется в результат | `//` пропускается до конца строки; `/*` переводит в блок; `"` переводит в строку; `'` переводит в символ |
| Строка | Всё копируется как есть, `\"` пропускается парой | Закрывающая `"` возвращает в код |
| Символ | Всё копируется как есть, `\'` пропускается парой | Закрывающая `'` возвращает в код |
| Блок `/* */` | Содержимое отбрасывается | После `*/` возврат в код |
 
После очистки `parseIncludes` разбивает текст на строки и ищет в каждой директиву регулярным выражением `^\s*#\s*include\s*"([^"]+)"`.
 
### Функция `findCycle`
 
Поиск в глубину (DFS) от стартового файла. Обход ведётся с двумя структурами: множеством посещённых вершин и текущим путём. Если из текущей вершины найден сосед, который уже посещён и при этом находится в текущем пути, значит, найден цикл. Он собирается как срез пути от этого соседа плюс сам сосед, поэтому первый и последний элементы цепочки совпадают. Если сосед посещён, но в пути его нет, это уже проверенная ветка, и она пропускается.
 
### Структуры данных
 
- `edges: Map<string, Set<string>>` в `DependencyGraph` - списки смежности графа;
- `processed: Set<string>` в `activate` - файлы, уже просканированные в `scanFile`, защита от повторного и бесконечного обхода;
- `visited: Set<string>` и `path: string[]` в `findCycle` - посещённые вершины и текущий путь DFS;
- строка `result` и индекс `i` в `cleanFile` - сборка очищенного текста и посимвольный обход.

### Последовательность работы
 
1. Пользователь вызывает команду `cpp-include-overlapping-detector.analyze`.
2. VS Code активирует плагин (вызывает `activate`) и запускает функцию команды.
3. Проверяется, что открыт редактор и папка проекта, иначе показывается предупреждение или ошибка.
4. `scanFile` читает стартовый файл, `cleanFile` очищает его, `parseIncludes` возвращает список подключений.
5. Для каждого `#include` путь отображается относительно каталога текущего файла, в граф добавляется ребро, и файл сканируется рекурсивно (глубина не более 20, повторно файлы не обходятся).
6. `findCycle` ищет цикл, начиная со стартового файла.
7. Если цикл найден, пути в нём приводятся к относительным (от корня проекта) и показываются уведомлением об ошибке в виде `a.h -> b.h -> a.h`.
8. Если цикла нет, показывается уведомление с числом проанализированных файлов. 

## Техническое задание

### Назначение

Автоматический поиск циклических зависимостей между файлами C++, возникающих из-за `#include "..."`, и показ цепочки файлов, образующих цикл.

### Функциональные требования

1. Плагин добавляет в VS Code команду «C++ Include Overlapping Detector: анализировать» (идентификатор `cpp-include-overlapping-detector.analyze`).
2. Анализ начинается с файла, открытого в активном редакторе. От него рекурсивно обходятся все файлы, подключаемые через `#include`.
3. Учитываются только локальные подключения вида `#include "..."`. Допускаются пробелы вокруг `#` и перед `include`.
4. Подключения вида `#include <...>` не учитываются.
5. Не считаются подключениями и не учитываются:
   - `#include`, закомментированные с помощью `//` или `/* ... */`;
   - текст `#include "..."` внутри строк.
6. Каждый файл обрабатывается не более одного раза.
7. Глубина рекурсивного обхода ограничена 20 уровнями.
8. Файлы, которые не удалось прочитать, пропускаются, анализ продолжается.
9. Если в графе подключений, достижимом из начального файла, есть цикл, плагин показывает сообщение об ошибке с цепочкой файлов вида `a.h -> b.h -> a.h`. Первый и последний файлы цепочки совпадают, пути указываются относительно корня проекта.
10. Если цикл не найден, плагин показывает информационное сообщение с количеством проанализированных файлов.
11. Если найдено несколько циклов, показывается только один из них.
12. Если ни один файл не открыт, плагин показывает предупреждение «Откройте C++ файл для анализа» и ничего не делает.
13. Если не открыта папка проекта, плагин показывает сообщение об ошибке «Откройте папку проекта» и ничего не делает.
14. Плагин не изменяет файлы проекта: анализ только читает файлы.

### Нефункциональные требования

- Плагин запускается только при вызове команды.
- Для работы не нужны внешние библиотеки и серверы: используются только API VS Code и стандартные модули Node.js (`fs`, `path`).
- Результат работы отображается уведомлениями VS Code и не создаёт дополнительных файлов в проекте.
- Код написан на TypeScript, все функции и методы снабжены TSDoc-комментариями, документация генерируется автоматически утилитой TypeDoc и хранится в репозитории.

### Ограничения

- Условная компиляция (`#ifdef`, `#pragma once`, include guards) не анализируется, цикл по `#include` будет показан.
